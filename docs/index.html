01 — NETWORK

KUB Testnet

Maddeth is configured for KUB Testnet with chain ID 25925, native currency tKUB, RPC https://rpc-testnet.bitkubchain.io and explorer https://testnet.kubscan.com.

The frontend does not invent deployment addresses. Until the deployment workflow records validated contracts, Live mode shows unavailable values and transactions remain disabled.

02 — LENDING FLOW

Wrap → supply → collateral → borrow.

The KUB Testnet lifecycle is designed around explicit wallet confirmations. Native tKUB can be wrapped to WtKUB, approved to the pool, supplied, enabled as collateral and used to borrow a configured test asset.

Repay and withdraw live on the dedicated Borrow page. Wallet rejection, wrong-network states and unavailable deployment state fail closed.

03 — MARKETS

Dedicated market pages.

Markets are no longer embedded in the marketing homepage. The application exposes a market directory plus individual WtKUB, mUSDC and mUSDT pages showing current supply rate, borrow rate, utilisation, liquidity and collateral parameters.

04 — RISK

Borrow capacity is explicit.

Borrow previews use current collateral value, market LTV, liquidation thresholds and existing debt. The interface blocks a requested borrow when the projected debt exceeds borrow capacity.

05 — RWA

Credit risk stays isolated.

The current RWA vault is a KUB Testnet demonstration only and does not represent a legally enforceable real-world asset. RWA debt and deposits remain outside pooled crypto lending accounting.

06 — SECURITY

Testnet hardened. Audit pending.

Current safeguards include stale-oracle rejection, market caps, emergency pause controls, two-step ownership, isolated RWA accounting, Foundry tests, static analysis and deployment-time bytecode/smoke checks.

Production deployment still requires independent audit, production oracle policy, economic review and multisig/timelock governance.
